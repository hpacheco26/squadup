SquadUp / product + engineering proposal / 15 Oct 2026

Seasons, counted in games.

A season ends after a set number of games - default 48 - or when an admin ends it early. The final table is archived, everyone resets to rank 0, and the next season starts immediately. At launch nothing is wiped: existing groups keep their ranks as Season 0, and the first fresh season is Season 1. No timers or background jobs; normal Firestore usage still applies.

Proposal only. No groups, rankings, or production data have been changed. The screen controls below are static mockups, not working controls.

What it shows

The season that ended, the player's final rank and leaderboard position, their W/D/L, and the group's champion and total games - all read from the archived final table.

Why it's cheap and safe

A small season:lastSeen marker per player detects the change on their next visit. It replaces the rank-down screen for that moment, so a reset never looks like a demotion. Shown once, then acknowledged.

03 / technical design

Keep today's structure. Add a counter and an archive.

Where ranks live - unchanged

Live ranks already sit inside each group's player list. Seasons add a small counter on the group and a read-only snapshot of each finished season. No data re-architecture, no new database layer.

The trigger already exists

Finishing a game already updates ranks today. We add two steps at the end: bump the counter, and if it hit the target, archive the table and reset. The one-game-per-group rule means there is never an ambiguous boundary.

Nothing runs in the background

No scheduler, no timezones, and no calendar math. Completed games drive progress. Billing depends on the project's plan and Firestore usage, not a new scheduled service.

Start lean, harden later if ever needed

The client starts a Firestore transaction that commits results, season progress/reset, debt, deletion and the next fixture together. Immutable completion receipts stop duplicate results. Manual ending checks the current season and live-game pointer.

04 / safe rollout

Existing groups start on Season 0. Nothing is wiped.

  1. Helpers + data

    Counter, reset and recap helpers and group fields, with unit tests. Keep today's rank rules.

  2. Completion + reset

    Extend end-of-game; add admin "End season now"; archive the table.

  3. UI

    Season line + progress, history, season-end recap, English + Portuguese.

  4. Migrate

    Backup, dry-run, then per-group: add season fields as Season 0. Ranks untouched.

Migration, in one line: for each group, attach season fields and label the current standings Season 0 - no ranks reset, nothing financial changed. The first reset happens later, when Season 0 ends and Season 1 begins. The script is resumable and needs explicit approval to apply.

Production deployment is a separate, explicit approval. Confirmed: season length counted in games (default 48, admin-set); manual early end (blocked while a game is live); archived tables; immediate renewal; per-player season recap; no reset at launch (Season 0 carries over, Season 1 is the first fresh season); reset leaves debts/membership untouched.
